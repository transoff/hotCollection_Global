# Умный роутинг выплат

5 Place in Hack.Genesis 2026 in the next hack could be better - https://buildin.ai/share/6ddf838b-8f69-4254-8b0a-466efee62a7a?code=KBFC5P


Роутер распределяет выплаты между платёжными провайдерами: отбирает допустимых по
hard-constraints, выбирает лучшего по экономике и целям распределения, при отказе
переходит к следующему, а если допустимых не осталось — уходит на self-provider
`spacepayments`. Каждое решение объясняется: кто рассматривался, почему выбран
именно этот и по какой причине исключены остальные.

Требуется только Ruby из стандартной поставки, внешних зависимостей у решения нет.

## Файлы сдачи

В корне репозитория лежат два файла, сформированные из `data/operations_queue_test.json`:

- `routing_decisions_test.json` — решение по каждой из 90 заявок
- `routing_report_test.json` — аналитика роутинга и рекомендации

Воспроизвести их можно одной командой (существующие файлы не перезаписываются —
сначала уберите старые):

```sh
ruby scripts/prepare_submission.rb --queue data/operations_queue_test.json
```

Скрипт прогоняет роутер, сверяет решения с исходной очередью и с отчётом и только
после этого кладёт оба файла в корень.

## Запуск роутера

```sh
# обработать очередь, результат в stdout
ruby prototype/simple_router/cli.rb --queue data/operations_queue_test.json --quiet --no-files

# со всеми артефактами прогона в отдельный каталог
ruby prototype/simple_router/cli.rb --queue data/operations_queue_test.json --output-dir out

# детерминированный прогон (без гонки воркеров за остаток лимита)
ruby prototype/simple_router/cli.rb --queue data/operations_queue_test.json \
  --workers 1 --arrival-mode batch --sleep-scale 0 --quiet --no-files

ruby prototype/simple_router/cli.rb --help   # все флаги
```

Полезные флаги: `--workers` (по умолчанию 8), `--seed`, `--scenario`
(`flat` / `size_sensitive` / `degraded` / `all_reject`), `--budget-pct`,
`--quantiles`, `--arrival-mode` (`created_at` реиграет поступления по
`created_at`, `batch` отдаёт всю очередь сразу).

## Правила роутинга

**Hard-constraints** — допуск провайдера к заявке. Нарушение любого исключает
провайдера независимо от стратегии: статус, диапазон суммы, дневной лимит,
лимиты in-progress по количеству и сумме, фильтр банков, отрицательная маржа,
свободные реквизиты, лимит запросов в минуту.

**Soft-goals** — предпочтение внутри уже допустимого пула. Сравниваются
лексикографически в порядке `goal_order`: `daily_turnover_min`,
`traffic_percentage`, `volume_share_pct`. Отклонение от максимума по прибыли
оплачивается «уступкой» в копейках из дневного бюджета (`budget_pct`), поэтому
мягкая цель не может бесконтрольно съедать экономику. При конфликте целей
выбирается кандидат с наименьшей уступкой на единицу улучшения цели.

**Каскад и fallback.** Отказавший провайдер исключается из пула, заявка
переоценивается заново на оставшихся. Если допустимых не осталось — заявка
уходит на `spacepayments`, и он всегда последний в каскаде.

Все параметры меняются через `prototype/simple_router/settings.json` или флаги
CLI, без правки логики. Цели по провайдерам задаются там же, в `provider_goals`.

## Структура

```
prototype/simple_router/
  router.rb      состояние провайдеров, отбор и резерв, учёт, каскад
  analytics.rb   настройки, деньги, квантили сумм, оценка качества,
                 hard-constraints, политика выбора
  harness.rb     расписание поступлений, часы стенда, прогон, отчёт
  cli.rb         разбор аргументов, чтение входных файлов, артефакты
  settings.json  параметры по умолчанию
data/            входные данные и очередь для сдачи
scripts/         автопроверка организаторов, подбор seed, сборка сдачи
fuzz/            фаззинг-харнессы и регрессии (см. fuzz/README.md)
```

## Проверки

```sh
ruby fuzz/regression_test.rb                                   # 9 регрессий
ruby scripts/validate_10.rb <файл_решений>                     # автопроверка
ruby scripts/pick_seed.rb data/operations_queue_10.json 1 25   # проходящие seed
```

Регрессии закрывают находки фаззера: очередь не в UTF-8, битая строка истории,
конфликтующий дубль `operation_id`, конкурентный захват остатка лимита,
освобождение резервов и позиция fallback в каскаде.
